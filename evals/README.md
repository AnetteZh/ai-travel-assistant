# Проверки и качество

Модуль `src/trip_checks` и папка `evals/`: всё, что проверяет агента кодом и меряет его качество.

## Что где

| Файл | Что делает |
|---|---|
| `src/trip_checks/plan_checks.py` | `check_plan`: состыковки поездки с учётом часовых поясов. `check_cart`: бюджет |
| `src/trip_checks/guardrails.py` | Защита ответа: убирает внутренние id и имена полей, заменяет коды рисков словами, вырезает предложения с числами, которых нет в данных (`UNSUPPORTED_NUMBER`) |
| `evals/golden.jsonl` | Эталон: 47 запросов с ожидаемым разбором, из них 10 — отложенная часть (`holdout`) |
| `evals/run_golden.py` | Точность разбора запроса по полям (нужен ключ модели) |
| `evals/scenarios.py`, `evals/run_scenarios.py` | 10 сквозных сценариев и метрики из ТЗ |
| `tests/test_trip_checks.py`, `tests/test_guardrails.py`, `tests/test_eval.py` | Юнит-тесты на каждое правило |

## Правила check_plan

Серьёзность согласована с `BLOCKING_CODES` в `graph.py`: `error` — план невозможен, корзина не считается, граф отправляет план на починку (`_repair_plan`). `warning` — показываем риск пользователю.

| Код | Когда срабатывает | Серьёзность |
|---|---|---|
| `DATE_MISMATCH` | Рейс туда уже ушёл; прибытие не в день заезда; обратный рейс не в день выезда (всё в местном времени направления) | error |
| `DATE_MISMATCH` | Обратный рейс раньше прибытия | error |
| `LATE_ARRIVAL` | Трансфер не работает при прибытии | error |
| `LATE_ARRIVAL` | Ресепшен закрыт к моменту приезда в отель (прибытие + дорога на трансфере) | warning |
| `CHECKIN_GAP` | Ждать заселения больше 4 часов | warning |
| `TIGHT_CONNECTION` | Трансфер привозит к терминалу меньше чем за 90 мин до вылета или 30 мин до поезда | warning |
| `TRANSFER_OUTSIDE_HOURS` | Трансфер к терминалу не работает | error |
| `NON_REFUNDABLE` | Невозвратный тариф | warning |
| `PETS_NOT_ALLOWED` | Питомец едет, а отель не принимает животных | error |
| `WEATHER_RISK` | Осадки ≥ 60% или хотят моря, а днём ниже 20°C | info |
| `OVER_BUDGET` | Итог корзины выше бюджета, с процентом | warning |

## Как запускать

```bash
make checks           # тесты проверок, ~3 секунды
make eval             # сценарии офлайн, без модели; отчёт в evals/reports/
make golden           # точность разбора на dev-части (нужен ключ в .env)
make golden-holdout   # честная оценка на отложенной части
python -m evals.run_scenarios --live   # сценарии с настоящей моделью
```

Holdout не открываем, пока настраиваем промпт: иначе цифра перестанет быть честной.

## Результат на офлайн-сценариях

Финальные планы всех трёх версий проверены одним и тем же `check_plan`, 8 сценариев дошли до корзины.

| | Первая версия Core | После правок Core (дата прибытия, починка) | После слияния с проверками |
|---|---|---|---|
| Планов с ошибками в состыковках | 7 из 8 | 7 из 8 | 0 из 8 |
| Ошибок в состыковках всего | 19 | 7 | 0 |
| Из них агент показал пользователю | 0 | 0 | — |

Оставшиеся после правок Core 7 ошибок — трансфер в аэропорт, который привозил ровно к вылету: исправлено в `travel_data/tools.py` (запас 90 мин до самолёта, 30 мин до поезда).

## Три способа оценки — чем отличаются

| | `scripts/eval_agent.py` + `agent_cases.json` | `evals/run_golden.py` + `golden.jsonl` | `evals/run_scenarios.py` |
|---|---|---|---|
| Модель | нужна | нужна | не нужна |
| Что проверяет | многоходовые диалоги целиком, какие блоки показаны, было ли уточнение | точность разбора запроса по каждому полю, есть отложенная часть | сборку, состыковки, починку, пересборку, бронь |
| Когда гонять | перед демо | после правки промпта | после каждого изменения в main, за секунду |
