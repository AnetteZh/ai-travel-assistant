# Путеводитель по файлам `travel_data_starter`

Документ написан для человека, который впервые открыл этот проект. Здесь объясняется, за что отвечает каждая папка и каждый файл, что запускается при старте и какие файлы безопасно менять.

## 1. Что делает весь проект

Это **модуль с данными и инструментами** для AI-агента путешествий. Это ещё не полноценный сайт и не сам чат-бот.

Внутри есть искусственный (синтетический) мир путешествий: направления, отели, маршруты и трансферы. Погоду модуль старается получить из внешнего API: сначала MET Norway, затем Open-Meteo. Если оба источника недоступны, модуль использует синтетическую климатическую оценку и честно помечает её как синтетическую.

Путь данных примерно такой:

1. Агент или демо-программа вызывает функцию, например `search_hotels()`.
2. `models.py` описывает, какие поля должны быть у запроса и ответа, и проверяет типы данных.
3. `world.py` загружает `world.json`.
4. `tools.py` ищет подходящие варианты, фильтрует их, считает оценки, суммы и причины выбора.
5. Функция возвращает структурированный объект. Если агент работает на LangGraph, `langgraph_adapter.py` позволяет зарегистрировать эти функции как tools.
6. `tests/` содержит автоматические проверки, чтобы замечать поломки после изменений.

## 2. Файлы в корне проекта

### `README.md` — основная инструкция

Описание возможностей, установка, команды запуска, погода и примеры подключения к LangGraph. Если нужно быстро вспомнить команды — начинай с этого файла.

### `FILE_GUIDE.md` — подробная карта файлов

Текущий документ. Здесь объясняется назначение файлов простыми словами.

### `pyproject.toml` — паспорт Python-проекта

В нём написаны название и версия проекта, версия Python, обязательные библиотеки и дополнительные зависимости.

- `pydantic` проверяет структуру данных.
- `httpx` делает HTTP-запросы к погодным API.
- `python-dotenv` читает настройки из `.env`.
- `tzdata` предоставляет базу часовых поясов, в частности на Windows.
- дополнительные зависимости `langgraph` нужны для подключения инструментов к LangGraph;
- `pytest` нужен для запуска тестов.

Команда `pip install -e ".[test,langgraph]"` читает этот файл и устанавливает пакет вместе с тестовыми и LangGraph-зависимостями.

### `.env.example` — пример настроек

Это шаблон, который можно скопировать в `.env`. Он содержит переключатели погодных провайдеров, таймауты, контакт для `User-Agent` MET Norway и путь к файлу с данными.

Настоящие локальные настройки обычно кладут в `.env`. Не добавляй секреты и приватные ключи в Git. Для текущего проекта OpenAI-ключ не нужен: LLM-обогащение удалено.

### `.gitignore` — что Git не должен сохранять

Здесь перечислены временные и локальные файлы: виртуальное окружение `.venv`, Python-кэш, `.pytest_cache`, локальный `.env` и временные JSON-файлы. Эти файлы не являются исходным кодом проекта и обычно не должны попадать в репозиторий.

### `Makefile` — короткие команды (необязательный)

Содержит удобные сокращения:

- `make seed` запускает генератор мок-мира;
- `make validate` проверяет мир;
- `make test` запускает тесты;
- `make demo` запускает демо;
- `make clean` удаляет некоторые временные файлы.

Для работы в Windows PowerShell `Makefile` не обязателен: можно выполнять команды `python ...` напрямую. Чтобы вызывать `make`, нужна отдельная программа `make`.

## 3. Данные

### `data/world.json` — основной файл мок-мира

Это большой JSON-файл с данными, с которыми работает программа: направления, отели, шаблоны рейсов/поездов и трансферов. Данные синтетические, не каталог реальных предложений для покупки.

Именно здесь можно посмотреть конкретные записи и поля. Например, у отеля есть ID, название, город, цена за ночь, звёзды, рейтинг, бассейн, правила размещения питомцев, политика отмены, удобства и координаты.

**Важно:** `python scripts/generate_world.py` перезаписывает этот файл. Если ты вручную исправила цену или описание и не хочешь потерять правки, сначала сделай копию.

### `src/travel_data/data/world.json` — копия данных внутри Python-пакета

Это вторая копия того же мира. Она нужна, чтобы пакет мог найти данные, даже когда будет установлен отдельно от исходной папки проекта.

Генератор обновляет обе копии. Не редактируй только одну копию вручную: данные могут разойтись. По умолчанию `world.py` сначала выбирает `data/world.json` из папки проекта; если его нет, использует файл внутри пакета.

## 4. Скрипты из `scripts/`

### `scripts/generate_world.py` — генератор мира

Создаёт направления, 200 отелей, шаблоны транспорта и трансферов по заданным правилам. Он использует код, а не LLM, поэтому результат воспроизводим и для генерации не нужен API-ключ.

Запуск:

```powershell
python scripts/generate_world.py
```

Скрипт записывает результат в обе копии `world.json`. Запускай его, когда специально хочешь пересоздать исходный мок-мир. Не нужно запускать перед каждым демо.

### `scripts/validate_world.py` — проверка согласованности данных

Проверяет, что у записей есть уникальные идентификаторы, ссылки ведут на существующие направления, транспорт и трансферы покрывают необходимые пункты, а базовые поля удовлетворяют правилам.

Запуск:

```powershell
python scripts/validate_world.py
```

Сообщение `WORLD OK` означает, что проверки этого скрипта пройдены. Это не означает, что внешний API погоды доступен: сетевые запросы эта проверка не тестирует.

## 5. Код основного пакета `src/travel_data/`

### `__init__.py` — короткий вход в пакет

Собирает наиболее полезные модели и функции в одном месте. Благодаря этому можно писать `from travel_data import search_hotels`, вместо необходимости импортировать функцию по длинному внутреннему пути.

### `models.py` — правила формы данных

Здесь описаны Pydantic-модели: какие поля есть у запроса на поездку, отеля, транспорта, трансфера, погоды, корзины и бронирования.

Примеры:

- `TravelBrief` — гости, жёсткие требования, мягкие пожелания и настроение;
- `TravelRequest` — эти пожелания плюс город отправления, даты, бюджет и веса ранжирования;
- `HotelRecord` — запись об отеле;
- `Evidence` — ссылка на источник конкретного факта;
- `WeatherSummary` — единый формат результата погодного API;
- `Cart` — рассчитанная корзина;
- `BookingResult` — результат демонстрационной брони.

У моделей строгие правила: неизвестные поля запрещены, многие значения ограничены (например, звёзды отеля от 1 до 5), а некорректный диапазон дат отклоняется. Это помогает ловить ошибки у границ между модулями.

### `world.py` — загрузчик мок-мира

Находит нужный `world.json`, читает JSON и проверяет его через `WorldData` из `models.py`. Также ищет направление по ID/названию и отель по ID.

Загрузка кешируется в памяти, чтобы файл не читать заново при каждом вызове. `reload_world()` сбрасывает этот кеш. Если ты изменила JSON во время уже запущенного процесса, программа может продолжать видеть старую версию до перезагрузки мира или перезапуска Python.

### `codes.py` — словарь причин и рисков

Хранит расшифровки кодов, которые появляются в результатах, например:

- `MATCHES_HARD` — выполнено жёсткое требование;
- `FREE_CANCELLATION` — есть бесплатная отмена;
- `OVER_BUDGET` — стоимость превысила бюджет;
- `LATE_ARRIVAL` — время прибытия не совпадает с часами работы трансфера;
- `PETS_NOT_ALLOWED` — отель не принимает питомцев.

Это не поиск и не расчёт: файл объясняет смысл кодов. Сами условия, при которых коды добавляются, находятся преимущественно в `tools.py` и в проверках интеграции.

### `tools.py` — основная логика Data

Это главный рабочий файл модуля. В нём находятся функции, которые вызывает агент:

- `suggest_destinations()` — предлагает направления и объясняет, почему они могут подойти;
- `search_hotels()` — фильтрует и ранжирует отели по жёстким требованиям и мягким пожеланиям;
- `search_transport()` — подбирает синтетические варианты перелётов/поездов туда и обратно, рассчитывает время и учитывает часовые пояса;
- `search_transfers()` — ищет трансфер между аэропортом/вокзалом и отелем и проверяет часы работы;
- `price_cart()` — считает цену выбранного варианта программно, а не просит LLM складывать числа;
- `book()` — создаёт только демонстрационную бронь с номером `DEMO-...`; реальные поставщики и оплата не вызываются;
- `get_weather()` — получает погоду: сначала MET Norway, затем Open-Meteo, потом использует синтетическую климатическую оценку.

В этом же файле находятся вспомогательные функции фильтрации, ранжирования, расчёта цен, формирования `Evidence`, обработки погодных ответов и кэширования. Если нужно менять правила поиска или расчёта — скорее всего, начинать надо отсюда.

### `langgraph_adapter.py` — переходник к LangGraph

Преобразует функции Data в инструменты формата LangChain, которые можно передать агенту LangGraph. Это адаптер — переходник между двумя частями программы.

Если Core AI подключает Data через LangGraph, файл нужен. Если функции вызываются из обычного Python или напрямую из узлов графа без регистрации как LangChain tools, сам адаптер необязателен. Базовые функции Data не зависят от него.

## 6. Демо и тесты

### `examples/run_demo.py` — демонстрация полного сценария

Показывает путь: предложить направления → выбрать отель → найти транспорт → найти трансфер → посчитать корзину → создать демо-бронирование.

Сценарий в этом файле задан заранее для примера: он выбирает Сочи через `destination_id = "dest-sochi"`. Поэтому повторные запуски не являются свободным диалогом и не должны каждый раз выбирать новый город или отель. Внешняя погода может обновляться, а идентификаторы корзины и демо-брони — меняться.

Запуск:

```powershell
python examples/run_demo.py
```

### `tests/test_data_tools.py` — автоматические тесты

Проверяет важные случаи: число и свойства записей мира, фильтр обязательных требований, выдачу альтернатив, путь через транспорт/трансфер/корзину/демо-бронирование, fallback погоды и использование погодного провайдера в предусмотренных сценариях.

Запуск:

```powershell
pytest -q
```

`6 passed` или аналогичный счётчик означает, что тесты прошли. Количество тестов может измениться после добавления новых проверок.

## 7. Можно ли удалить LLM-файл?

В этой версии проект работает без LLM. Необязательный файл `scripts/enrich_hotels_with_openai.py` удалён: он не использовался при запуске демо и не нужен для поиска отелей. Раньше он позволял попросить модель придумать другие названия и описания отелей, сохраняя ID, цены, координаты и булевы признаки.

Удаление этого скрипта не удаляет названия и описания из `world.json`: они уже являются обычными данными. Если когда-то запускалась LLM-обработка и нужно вернуть исходный детерминированный мир, можно запустить `python scripts/generate_world.py`, но это перезапишет обе копии JSON и удалит также ручные правки в них.

## 8. Что не входит в этот модуль

Здесь нет React/Next.js-интерфейса, отображения настоящих UI-карточек, FastAPI-сервера или полного диалогового AI-агента. Это отдельная часть общего проекта. `travel_data` предоставляет данные и функции, которыми другие части приложения пользуются.
