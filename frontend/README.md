# О!дин запрос — Frontend v3.2

Что нового в v3.2 — см. `RELEASE-v3.2.md`.

Новая версия интерфейса для хакатона Островка: яркие акценты «Мохито» и «Ультрамарин», крупные карточки направлений, чат-консьерж справа. Это самостоятельный **демонстрационный проект**, не официальный сайт Островка.

## Как распаковать **на Windows**

Архив содержит верхнюю папку `frontend` **целиком**, включая `package.json`. Распакуй архив сначала в «Загрузки» и убедись, что ты видишь `frontend/package.json`. Затем перенеси содержимое этой папки в `C:\Users\Софа\Documents\ostrovok-project\frontend` с заменой файлов. Не помещай её внутрь `frontend/frontend`. Не трогай `src/agent_core` и `src/travel_data`.

Если в существующем `frontend` есть файл `.env.local`, сохрани его, он содержит адрес Core. `node_modules` копировать из архива не требуется.

```powershell
cd "C:\Users\Софа\Documents\ostrovok-project\frontend"
Test-Path .\package.json    # должно быть True
npm install
npm run dev -- -p 3001
```

Открывай **http://localhost:3001**. Если после замены файлов старый интерфейс не исчез, останови сервер (`Ctrl+C`), очисти кэш `.next` и запусти повторно:

```powershell
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
npm run dev -- -p 3001
```

Проверь масштаб браузера: `Ctrl+0` → 100%. На присланном скриншоте масштаб был 80%.

## Настоящие страницы и навигация

| URL | Экран |
| --- | --- |
| `/` | Главная с крупным hero, темами путешествия и быстрым переходом |
| `/destinations` | Направления и карточки |
| `/selection` | Подбор отелей, сравнение, таймлайн и действия агента |
| `/checkout` | Корзина, пересборка бюджета и демонстрационное оформление |

Верхнее меню, лого, «Назад» и «На главную» работают через Next.js App Router. Кнопка **Назад** в интерфейсе возвращает на предыдущий **логический этап**; клавиша Back в браузере возвращает на предыдущий фактический URL. Данные чата/поездки хранятся в `TripProvider` и в `sessionStorage` — сохраняются при переходах и перезагрузке страницы в пределах этой вкладки. «Новая поездка» сбрасывает сессию.

## Тестовый сценарий без API

1. Главная → «Начать путешествие» → `/destinations`.
2. Выбери «Сочи» → `/selection` и посмотри отели и маршрут.
3. Нажми «К корзине» → `/checkout`.
4. Укажи новый бюджет → «Пересобрать» → покажется `plan_diff`.
5. Нажми «Оформить демо-бронь» → откроется модальное окно с **имитацией**, без платежа.
6. Перейди «Назад», «Главная», потом «Корзина» и убедись, что выбранная поездка сохранилась.
7. Проверь стрелки браузера Back и Forward и обнови страницу клавишей `F5`.

Все предложения в Demo — синтетические UI-фикстуры (никаких реальных броней и источников цен). Фотографии — **иллюстративные**, не фотографии конкретных отелей.

## Интеграция с Core

Создай `frontend/.env.local`:

```env
CORE_API_URL=http://127.0.0.1:8765
```

В корне **Core-проекта** после настройки Python-зависимостей и `.env` запускается:

```powershell
python -m uvicorn agent_core.api:app --app-dir src --host 127.0.0.1 --port 8765
```

В UI переключись на «Настоящий агент». Next.js проксирует запросы в Core:

| Браузер → Next.js | Next.js → Core | Зачем |
| --- | --- | --- |
| `POST /api/agent/chat` | `POST /chat` (SSE `status/block/complete/error`) | Сообщения в чате |
| `PATCH /api/agent/trips/:id` | `PATCH /trips/:id` | Бюджет, выбор и сброс направления |
| `POST /api/agent/trips/:id/book` | `POST /trips/:id/book` | Демо-бронь (в Core ручки пока нет) |

Core хранит сессии в памяти: после его перезапуска старая поездка теряется. Интерфейс это
замечает и предлагает начать заново, а выбор направления сам начинает новую сессию.

**Бронирование.** Пока в FastAPI нет `POST /trips/{id}/book`, Core отвечает 404, и демо-бронь
оформляется на стороне интерфейса с явной пометкой. Когда ручку добавят, фронт начнёт показывать
номер заказа из Core без изменений в коде. При блокирующих несостыковках кнопка недоступна.

## Файлы, которые менялись в v3

- `src/components/travel-app.tsx` — единый layout и экраны с работающими ссылками.
