# v3.2: честный статус плана, понятные ошибки, рабочий выбор направлений

Дизайн v3.1 сохранён: страницы, маршруты, палитра и карточки те же. Изменилась логика.

## Что исправлено

1. **«Найти направления» в режиме настоящего агента.** Если в поездке уже есть город, кнопка
   «Подобрать другие направления» сбрасывает направление через `PATCH /trips/{id}` с
   `{"destination": null}`. Бюджет, гости и город вылета сохраняются. Раньше уходило сообщение
   в чат, и Core снова собирал поездку в Сочи.
2. **Выбор карточки направления** тоже идёт через PATCH `{"destination": "<город>"}`, без разбора
   текста моделью: быстрее и без ошибок распознавания.
3. **Статус «Всё собрано» больше не врёт.** Новый блок «Проверка плана» делит замечания Core на
   блокирующие (`DATE_MISMATCH`, `LATE_ARRIVAL`, `TRANSFER_OUTSIDE_HOURS`, любые `severity: error`)
   и предупреждения (`CHECKIN_GAP`, `OVER_BUDGET` и др.). При блокирующих оформление недоступно.
   Список кодов лежит в `src/lib/plan-health.ts`, его нужно согласовать с модулем проверок.
4. **Страховочные проверки интерфейса** (помечены «проверка интерфейса»): даты в прошлом и прибытие
   позже начала проживания. Core их пока не ловит; когда начнёт, перенести в `check_plan`.
5. **Ошибки.** В историю чата больше не добавляются одинаковые «Не получилось получить ответ».
   Вместо этого одна карточка ошибки с причиной (Core недоступен / модель не ответила / ответ
   оборвался / сессия потеряна) и кнопкой «Повторить». Текст запроса возвращается в поле ввода.
   Блоки обновляются только после события `complete`, поэтому оборванный ответ не ломает план.
6. **Перезапуск Core.** Если сервер потерял сессию, выбор направления и поиск автоматически
   начинают новую, а в чате появляется предупреждение. Для бюджета показывается «Начать заново».
7. **«Как агент понял запрос»**: откуда, куда, даты (с пометкой «предположение»), гости, бюджет.
   Так сразу видно, если модель не распознала город вылета. Одинаковые допущения схлопываются.
8. **«Что сделал агент»**: 3–5 главных шагов текущего запроса, полный список по кнопке.
   Раньше показывалось ~38 шагов за весь разговор.
9. **Синтетические данные**: в живом режиме «Подбор выполняет AI-агент. Данные об отелях,
   транспорте и ценах демонстрационные» и бейдж «Синтетические данные».
10. **Демо-бронь в живом режиме** работает. Фронт вызывает `POST /trips/{id}/book`; пока в Core
    такой ручки нет, заказ имитируется в интерфейсе, и это прямо написано в окне брони.
11. Мелочи: год в датах, если он не текущий; правильная иконка поезда/самолёта; читаемые
    названия позиций корзины («Поезд: Москва → Сочи» вместо «train: …»); нейтральная обложка
    для городов без иллюстрации вместо пальмы; навигация после ответа агента ведёт на нужную
    страницу; исправлены ошибки ESLint в `trip-provider.tsx`.

## v3.3 (вместе с исправленным Core)

- Если Core не посчитал корзину из-за блокирующих несостыковок, корзина показывает план,
  замечания и «Стоимость появится после исправления плана», а не «Корзина пуста».
- Плашки «Туда» и «Обратно» показывают транспорт, выбранный в плане, а не первый из выдачи.
- Время везде показывается местное для пункта, как в билете, без пересчёта в пояс браузера.
- В «Что сделал агент» видно, что именно исправил агент («заменила транспорт туда…»).
- Страховочная проверка интерфейса не дублирует `DATE_MISMATCH`, если его уже нашёл Core.
- Бронь в живом режиме оформляется через `POST /trips/{id}/book` в Core (нужна версия Core из PR).

## v3.2.1 (по итогам первого запуска с GigaChat)

- Если модель кладёт в `destination` внутренний id («dest-kaliningrad»), в заголовке и в
  «Как агент понял запрос» показывается название города.
- Неудачный запрос больше не оставляет сообщение в истории чата: текст возвращается в поле
  ввода, а «Повторить» добавляет его один раз. Раньше «Выходные без суеты» копились по три раза.
